## Current understanding

Skill libraries that improve from experience are a mainstream research line (Voyager, Reflexion, AWM, ACE, SkillWeaver, MemSkill, 2026 lifecycle surveys). The strongest practical results come from delta updates with helpful/harmful tagging and periodic dedupe (ACE), from recording the rationale behind every stored rule (the catastrophic-remembering study), and from curating rather than accepting self-generated rules. Full-file rewrites and unbounded appends both fail, in opposite ways.

Refresh scheduling has no agent-specific literature worth citing; the transferable results come from crawler freshness theory (Poisson change models, uniform beats proportional, sublinear response to change rate), TCP's AIMD, HTTP heuristic freshness (10% of age), backoff jitter, and the observation that event-driven invalidation beats any timer when a change signal exists (a user correction is such a signal).

Cross-agent portability has settled on `AGENTS.md` (Linux Foundation's Agentic AI Foundation) plus `SKILL.md` folders (agentskills.io, 45+ clients), with `.agents/skills/` emerging as the shared location. Claude Code still does not read `AGENTS.md` natively; `CLAUDE.md` containing `@AGENTS.md` is the documented bridge. Hooks vary by tool and several tools have none.

Codemaps help when short and human-grade and hurt when auto-generated and bloated (ETH Zurich, Feb 2026: LLM-generated context files cost 3% success and 20% more tokens). Stamp the commit, separate generated from hand-written sections, log what was verified.

Model knowledge is measurably stale on fast-moving topics (LLMLagBench cutoff drift; deprecated-API emission studies), which justifies research-first as a principle rather than a preference.

Staleness has a second axis besides facts: the tooling around a subject. As of September 2026 the AI ecosystem ships skills, plugins, MCP servers and memory or graph frameworks fast enough that a unit can hold every fact correctly and still describe a procedure something now does better. The discovery surfaces are settled enough to search on a schedule (skills.sh install telemetry, the official MCP registry, Anthropic's plugin catalogs, GitHub code search on `path:SKILL.md` and `path:.claude-plugin/marketplace.json`, the agent-skills topics and awesome lists) and popularity has a usable signal in install counts, with stars plus recent commits as the fallback; listing position on an SEO directory has none. Agent memory is the one area with no neutral benchmark, so vendor claims are read against each other. Practice reports are worth a track of their own because they carry the workflows and pitfalls that neither docs nor repos state.

Reporting self-updates by email (2026-09-03): Claude Code has a `SessionEnd` hook with a reason matcher; SessionEnd hooks share a 1.5 s budget by default, and as of 2026-09-10 the hooks reference says a longer per-hook `timeout` raises that budget to match, up to 60 s, so a short synchronous step is possible, though the mailer still runs detached because a send with attachments can outlast a minute and must never block exit; Copilot CLI (`sessionEnd`, `timeoutSec` default 30) and Codex (`SessionEnd`, synchronous, 1 s default, 3 s max) have the same shape. Cowork runs no hooks at all (issue #40495, open, and #63360, closed as its duplicate, confirm it ignores user, managed and plugin hooks; still true through Claude Code 2.1.267), so there the trigger is the `checked` command or a skill. Transports: the new Outlook has no COM object model (classic stays supported to at least 2029; new Outlook default from April 2026); delegated Graph `Mail.Send` is still user-consentable under Microsoft's 2026 secure-by-default policy; consumer Gmail app passwords still work (2-Step Verification required; 587 STARTTLS / 465; 500 recipients a day) and the "basic auth ended in 2025" claim circulating in blogs is false; Gmail accepts `.patch`, `.json`, `.md` and text-only zips but blocks `.ps1` even inside zips and rejects password-protected archives outright. `git apply --3way` needs the base blobs in the object database (hence pack tags), `git merge-file` returns the conflict count, GNU patch fuzz defaults to 2.

Testing skills (2026-09-04): skill evaluation is a measured discipline now, and the numbers are humbling. A relevant skill adds only 5 to 22 points of pass rate across ~500 open-source skills and 19 agent-model configurations (arXiv 2606.17819), and can be net negative: on 1,000 Web-Bench tasks with 31 web-dev skills and 4 models, skill injection lowered Pass@2 by 1.3 to 4.2 points while raising tokens 72 to 394%, helping in only 17 to 36% of skill-project pairs (arXiv 2608.23067); Vercel's Next.js evals saw a skill go unused in 56% of the tasks it was written for, so undertriggering is the dominant failure and an always-loaded AGENTS.md beat skills there. The first-party loop is Anthropic's skill-creator v2 (March 2026): `evals/evals.json` with prompts, files and verifiable expectations, one fresh subagent per case, `grading.json` with evidence, `benchmark.json` for with-versus-without, a blind A/B comparator, and a description improver (60/40 held-out split, three runs per prompt, up to five rewrite iterations). `claude plugin eval` was documented on 2026-09-04 as the CLI harness: `evals/<case>/prompt.md` plus `graders/*.md` (`regex`, `tool_used`, `tool_order`, `file_exists`, `llm` with 2-of-3 votes, `baseline`), three runs by default, an `aggregate-result.json`, exit codes for CI, early access per organization (confirmed on 2.1.259); by 2026-09-10 the command had been withdrawn from the public docs entirely (plugins reference, CLI reference and the docs index list only `claude plugin validate`), so that flag list is unverifiable from primary sources and the harness counts as undocumented early access, behind skill-creator's runner and the tester agent in TESTING.md §6; the Claude Code `/skill-doctor` command (GA in 2.1.261, 2026-09-04) is a usage-and-cost report, not a linter (a community plugin of the same name audits skills). Cross-vendor consensus on the shape: OpenAI's eval-skills guide splits criteria into outcome, process (was the skill invoked, were the intended tools called) and style, deterministic checks before rubric grading; obra/superpowers writes skills test-first (RED baseline in a subagent without the skill, GREEN with it, REFACTOR the loopholes). The silent no-op ("fake verification": the reply says the tests passed or the delegation happened, no tool output backs it) is the most reported Claude Code hallucination, and the mitigation everyone converges on is to grade the tool-call trace or a side effect, never the prose; Langfuse's trace-first evals add "skipped the skill" and "fell back to curl" as first-class failure rates. Third-party harnesses that can run a CLI agent with tool-call assertions: promptfoo (`claude-agent-sdk` provider, `trajectory:tool-used`), UiPath `coder_eval`, `smevals`, Inspect AI, DeepEval, EvalView; GEPA and SkillGrad optimize SKILL.md text against a sandboxed metric. Runtime observation: Claude Code `PreToolUse`/`PostToolUse` hooks take a tool-name matcher and receive `session_id`, `transcript_path`, `cwd`, `tool_name`, `tool_input`, `tool_response`, which is enough to log every skill invocation with a pointer to its transcript. Codex's `PostToolUse` payload carries `transcript_path` as well (learn.chatgpt.com/docs/hooks); Copilot CLI's `postToolUse` does not, only its `agentStop` has `transcriptPath`.

Contested or moving: whether Claude Code will adopt `.agents/skills/` and `AGENTS.md`; the exact `SKILL.md` frontmatter set (the skills reference on 2026-09-10 lists 20 fields, among them `when_to_use`, `effort`, `context`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`; `tags`, seen in earlier 2026 docs, is gone, and the 1,536-character cap covers `description` plus `when_to_use` together); whether `claude plugin eval` returns to the docs, GA or gated, and with which flags (withdrawn by 2026-09-10); whether subagent-run trigger tests predict main-loop triggering (no study either way); whether `outlook.exe /c ipm.note` still works on new-Outlook-only machines (no primary source either way); whether Gmail's compose URL keeps honoring `view=cm` (a 2024 report saw a redirect to `tf=cm`).

### R-20260917-1 · 2026-09-17 · Install-time consent for sending anything upstream: opt-in, stored outside the managed tree, DO_NOT_TRACK and CI as no, drafts in the user's name
- Summary: the reference precedents are opt-in after backlash: Go telemetry (default `local`, `go telemetry on|off|local`, state under the OS user config dir so upgrades keep it; https://go.dev/doc/telemetry) and Rust (no network from the compiler; https://internals.rust-lang.org/t/19275); Homebrew stores its flag inside the managed git tree and `brew analytics off` fails without a repo (Homebrew/brew#5933), the shape to avoid. Consent-file schemas converge on `enabled`, `decided_at`, `asked_by_version` in the user config dir with precedence env > `DO_NOT_TRACK=1` > `CI=true` > file > default off (y3l1n4ung/dust#529; claude-mem `~/.claude-mem/telemetry.json`, asked once at install, never re-asked). `DO_NOT_TRACK=1` is the one cross-tool signal (https://donottrack.sh/; Homebrew/brew#6745, dbt-core#3540). A skill that phones home silently is now reported as a defect (cashfree/agent-skills#33). GitHub's guidance on agent pull requests puts authorship on the human who deployed the agent, self-review not optional (github.blog, 2026-05; the matplotlib #31132 episode), so an automatic pull request needs a named consenting human and should open as a draft. Testing precedent: "zero egress before opt-in" CI gates and intercepted-send counts (sanenotes#944, sutando#4370); the transferable assertion is that with consent `no` the trace contains no push and no `gh pr create`. No project re-asks on a major version; the recorded `asked_by_version` lets one re-ask only when the shared content widens. Anthropic's marketplace has no convention to lean on (read-only mirror, form submissions), and plugin installs are cache copies replaced on update, so the choice cannot live there.
