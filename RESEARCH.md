## Current understanding

Skill libraries that improve from experience are a mainstream research line (Voyager, Reflexion, AWM, ACE, SkillWeaver, MemSkill, 2026 lifecycle surveys). The strongest practical results come from delta updates with periodic dedupe (ACE, whose helpful and harmful tags are statistics only: acting on the counts is this protocol's extension, nearer to ExpeL and Library Drift, and MUSE-Autoskill keeps per-skill lessons and tests the way a unit does), from recording the rationale behind every stored rule (the catastrophic-remembering study), and from curating rather than accepting self-generated rules (SkillsBench v4: self-generated skills score 8.1 to 11.5 points below none). Full-file rewrites and unbounded appends both fail, in opposite ways.

Refresh scheduling for agent knowledge is a named open problem (the July 2026 skill-library survey, 12.3), and nothing found re-researches stored knowledge from the web on an adaptive schedule: the nearest designs set intervals by popularity (Context7), by freshness class (FreshCache), by event (SkillGuard, repo wikis) or by hand (Cochrane living reviews), and Copilot Memory re-checks each memory against its cited code before use. The transferable theory still comes from crawler freshness (Poisson change models, uniform beats proportional under a fixed budget, sublinear response to change rate), TCP's AIMD, HTTP heuristic freshness (10% of age), backoff jitter, and the observation that event-driven invalidation beats any timer when a change signal exists (a user correction is such a signal). The plugin's own benchmark agrees with the crawler result: under memoryless change the rule spends about one to two checks per change and its reactive intervals cost 25 to 70 percent more delay than the same number of evenly spaced checks (R-20260923-10). Re-checking at use pays only where it is required: agents consult a memory's source about one time in five and act on superseded constraints three times in four unless a check is forced (R-20260923-2).

Cross-agent portability has settled on `AGENTS.md` (Linux Foundation's Agentic AI Foundation) plus `SKILL.md` folders (agentskills.io, 45+ clients), with `.agents/skills/` emerging as the shared location. Claude Code reads `AGENTS.md` natively since 2.1.277, but only when no `CLAUDE.md` or `CLAUDE.local.md` exists; otherwise a `CLAUDE.md` containing the import `@AGENTS.md` is the documented bridge, and one that says "read AGENTS.md" in words loads nothing (R-20260923-9). Hooks vary by tool and several tools have none.

Codemaps help when short and human-grade and hurt when auto-generated and bloated (ETH Zurich, Feb 2026: LLM-generated context files cost 3% success and 20% more tokens). Stamp the commit, separate generated from hand-written sections, log what was verified.

Model knowledge is measurably stale on fast-moving topics (LLMLagBench cutoff drift; deprecated-API emission studies), which justifies research-first as a principle rather than a preference.

Staleness has a second axis besides facts: the tooling around a subject. As of September 2026 the AI ecosystem ships skills, plugins, MCP servers and memory or graph frameworks fast enough that a unit can hold every fact correctly and still describe a procedure something now does better. The discovery surfaces are settled enough to search on a schedule (skills.sh install telemetry, the official MCP registry, Anthropic's plugin catalogs, GitHub code search on `path:SKILL.md` and `path:.claude-plugin/marketplace.json`, the agent-skills topics and awesome lists) and popularity has a usable signal in install counts, with stars plus recent commits as the fallback; listing position on an SEO directory has none. Agent memory has converged in 2026 on files the agent edits plus a background consolidation pass (Anthropic Dreams, OpenAI Dreaming V3, Letta Context Repositories); a coding agent over plain files beat RAG on LongMemEval-V2 (72.5 against 48.5 percent), the saturated benchmarks no longer separate vendors, and vendor claims are still read against each other (R-20260923-3). Practice reports are worth a track of their own because they carry the workflows and pitfalls that neither docs nor repos state.

Reporting self-updates by email (2026-09-03): Claude Code has a `SessionEnd` hook with a reason matcher; SessionEnd hooks share a 1.5 s budget by default, and as of 2026-09-10 the hooks reference says a longer per-hook `timeout` raises that budget to match, up to 60 s, so a short synchronous step is possible, though the mailer still runs detached because a send with attachments can outlast a minute and must never block exit; Copilot CLI (`sessionEnd`, `timeoutSec` default 30) and Codex (`SessionEnd`, synchronous, 1 s default, 3 s max) have the same shape. Cowork runs no hooks at all (issue #40495, open, and #63360, closed as its duplicate, confirm it ignores user, managed and plugin hooks; still true through Claude Code 2.1.267), so there the trigger is the `checked` command or a skill. Transports: the new Outlook has no COM object model (classic stays supported to at least 2029; new Outlook default from April 2026); delegated Graph `Mail.Send` is still user-consentable under Microsoft's 2026 secure-by-default policy; consumer Gmail app passwords still work (2-Step Verification required; 587 STARTTLS / 465; 500 recipients a day) and the "basic auth ended in 2025" claim circulating in blogs is false; Gmail accepts `.patch`, `.json`, `.md` and text-only zips but blocks `.ps1` even inside zips and rejects password-protected archives outright. `git apply --3way` needs the base blobs in the object database (hence pack tags), `git merge-file` returns the conflict count, GNU patch fuzz defaults to 2.

Testing skills (2026-09-04): skill evaluation is a measured discipline now, and the numbers are humbling. A relevant skill adds only 5 to 22 points of pass rate across ~500 open-source skills and 19 agent-model configurations (arXiv 2606.17819), and can be net negative: on 1,000 Web-Bench tasks with 31 web-dev skills and 4 models, skill injection lowered Pass@2 by 1.3 to 4.2 points while raising tokens 72 to 394%, helping in only 17 to 36% of skill-project pairs (arXiv 2608.23067); Vercel's Next.js evals saw a skill go unused in 56% of the tasks it was written for, so undertriggering is the dominant failure and an always-loaded AGENTS.md beat skills there. The first-party loop is Anthropic's skill-creator v2 (March 2026): `evals/evals.json` with prompts, files and verifiable expectations, one fresh subagent per case, `grading.json` with evidence, `benchmark.json` for with-versus-without, a blind A/B comparator, and a description improver (60/40 held-out split, three runs per prompt, up to five rewrite iterations). `claude plugin eval` was documented on 2026-09-04 as the CLI harness: `evals/<case>/prompt.md` plus `graders/*.md` (`regex`, `tool_used`, `tool_order`, `file_exists`, `llm` with 2-of-3 votes, `baseline`), three runs by default, an `aggregate-result.json`, exit codes for CI, early access per organization (confirmed on 2.1.259); withdrawn from the public docs by 2026-09-10, it returned with Claude Code 2.1.269 (2026-09-11), documented at code.claude.com/docs/en/plugin-evals: case folders, six grader types (no code graders), a no-plugin baseline arm by default, three runs per arm in a throwaway home and config, and shell-granting cases refused where no sandbox backend exists (native Windows), so it heads TESTING.md §6 again (R-20260923-7); the Claude Code `/skill-doctor` command (GA in 2.1.261, 2026-09-04) is a usage-and-cost report, not a linter (a community plugin of the same name audits skills). Cross-vendor consensus on the shape: OpenAI's eval-skills guide splits criteria into outcome, process (was the skill invoked, were the intended tools called) and style, deterministic checks before rubric grading; obra/superpowers writes skills test-first (RED baseline in a subagent without the skill, GREEN with it, REFACTOR the loopholes). The silent no-op ("fake verification": the reply says the tests passed or the delegation happened, no tool output backs it) is the most reported Claude Code hallucination, and the mitigation everyone converges on is to grade the tool-call trace or a side effect, never the prose; Langfuse's trace-first evals add "skipped the skill" and "fell back to curl" as first-class failure rates. Third-party harnesses that can run a CLI agent with tool-call assertions: promptfoo (`claude-agent-sdk` provider, `trajectory:tool-used`), UiPath `coder_eval`, `smevals`, Inspect AI, DeepEval, EvalView; GEPA and SkillGrad optimize SKILL.md text against a sandboxed metric. Runtime observation: Claude Code `PreToolUse`/`PostToolUse` hooks take a tool-name matcher and receive `session_id`, `transcript_path`, `cwd`, `tool_name`, `tool_input`, `tool_response`, which is enough to log every skill invocation with a pointer to its transcript. Codex's `PostToolUse` payload carries `transcript_path` as well (learn.chatgpt.com/docs/hooks); Copilot CLI's `postToolUse` does not, only its `agentStop` has `transcriptPath`.

Contested or moving: whether Claude Code will adopt `.agents/skills/` (its `AGENTS.md` support arrived in 2.1.277, behind any `CLAUDE.md`); the exact `SKILL.md` frontmatter set (the skills reference on 2026-09-10 lists 20 fields, among them `when_to_use`, `effort`, `context`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`; `tags`, seen in earlier 2026 docs, is gone, and the 1,536-character cap covers `description` plus `when_to_use` together); whether `claude plugin eval` stays documented (it vanished once without a changelog line, L-017); whether subagent-run trigger tests predict main-loop triggering (no study either way); whether `outlook.exe /c ipm.note` still works on new-Outlook-only machines (no primary source either way); whether Gmail's compose URL keeps honoring `view=cm` (a 2024 report saw a redirect to `tf=cm`).

## Findings log

### R-20260923-1 · 2026-09-23 · Adaptive re-research has no peer; the nearest designs schedule by popularity, class, event or hand, and a July survey names the schedule an open problem
- Summary: Two research passes on 2026-09-23 (the owner's note on knowledge-base paradigms) found no system, product or paper that re-researches stored knowledge from primary web sources on an adaptive schedule; the July 2026 skill-library survey lists it as open problem 12.3, "no principled schedule has emerged for balancing maintenance cost against library drift". The nearest designs: Context7 re-parses a library's docs on request when its copy is older than a popularity threshold (1 day for the top 100 libraries, 15 for the top 1,000, 30 for the top 5,000, 45 otherwise), so the interval follows popularity, not observed change; FreshCache fits a staleness half-life per freshness class from repeated crawls (timeless 22 days, slow 16 days, medium 15 hours, fast 3 hours) and reuses a cached answer only while the chance it is stale stays under a budget, 97 percent fewer search calls at 0.1 percent stale answers, per class and only when a query arrives; SkillGuard checks each skill's environment contracts against the live system when something changes (0 false alarms in 599 cases, against 40 percent for plain CI), with no scheduler; Repo2Skill-Evo found that every one of 105 releases broke some skills; GitHub Copilot Memory stores a citation with each memory, re-reads the cited code on the current branch before use, deletes a memory unused for 28 days, and measured a 90 against 83 percent pull-request merge rate with and without memory; Cochrane living systematic reviews search monthly and other sources every 3 or 6 months, set by people. Crawler theory (R-20260901-2) supplies the budget view: under a fixed revisit budget, uniform revisits beat chasing the fastest changers, and nothing in the protocol bounds research spend per unit (one unit's refresh that day used about 227K subagent tokens, six days after its due date).

### R-20260923-2 · 2026-09-23 · Re-checking at use pays, but only when it is required: agents consult a memory's source about one time in five
- Summary: Stale constraints (arXiv 2608.25553): models checked a memory's source in about one episode in five and still acted on a superseded constraint 74.7 to 77.3 percent of the time; forcing a check of the critical source added 61 to 74 points. STALE (arXiv 2605.06527): the best system recognised only 55.2 percent of memories that were no longer valid. Environment-probing curation (arXiv 2609.11060): re-checking stored memories with read-only tools lifted a pass rate from 39 to 73 percent. Copilot Memory's check-before-use (R-20260923-1) is the shipped form. For this protocol the lesson is that verify-at-use is worth keeping and worth making cheap: a unit re-checked only as a whole makes every use pay for every claim, which invites skipping the check, while a date on each claim lets Step 0 re-check only what is due and still force the check where it matters.
- Track: subject, testing · Magnitude: 0.5 (a step changed: Step 0 of a verify-at-use unit re-checks due claims, each claim carries its own date) · applied: C-20260923-5
- Sources: https://arxiv.org/abs/2608.25553 · https://arxiv.org/abs/2605.06527 · https://arxiv.org/abs/2609.11060 · https://arxiv.org/abs/2609.08258

### R-20260923-3 · 2026-09-23 · The 2026 convergence: memory as files the agent edits, plus a background consolidation pass
- Summary: Anthropic's Managed Agents memory stores mount as directories the agent edits, every write an immutable version; Dreams (research preview, beta header `dreaming-2026-04-21`) reads a store plus 1 to 100 session transcripts and writes a new store with duplicates merged and contradicted entries replaced, never touching the input store until a person switches. Where hooks exist the session-start audit can say it, at no cost when nothing is due, without a new hook event. External scoring (a LongMemEval-V2 or STALE-style probe of a docs unit) stays an open question.

### R-20260923-4 · 2026-09-23 · Retrieval at this scale: files plus keyword search are enough; a title-only lookup is not
- Summary: At personal and project scale the evidence favours files and keyword search over a vector store: LongMemEval-V2 (72.5 percent for a coding agent over files against 48.5 for RAG), Letta's filesystem benchmark (74.0 percent on LoCoMo with plain files and grep), and a PwC study in which grep beat vector search in 8 of 8 harness and model pairs when results came back inline (and lost when they came back as files); Cursor measured a 12.5 percent gain from adding a semantic index on large codebases. The gap in this protocol was narrower: the write-time gate (AUDN) and a refresh's "new, or already in RESEARCH.md?" both compared by title or by reading everything, so a near-duplicate in other words, or in another unit, went unseen. BM25 over the log entries, with light stemming and code-like tokens kept whole, closes that at no dependency cost; embeddings stay unneeded until an index keeps splitting past its budget.
- Track: tooling, subject · Magnitude: 0.3 (a new step in the gate and in refresh step 3) · applied: C-20260923-7
